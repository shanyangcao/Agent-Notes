#### 1. 向量存储实现类型

LangChain 提供两种核心向量存储方案：

- `**InMemoryVectorStore**`：内存级向量存储，数据仅存在运行内存中，适合调试与轻量场景。
- `**Chroma**`：外部数据库级向量存储，支持数据持久化，适合生产环境。

#### 2. 通用 API 接口

所有向量存储类均提供 3 个标准接口：

- `add_document` / `add_texts`：添加文档 / 文本到向量库（`add_texts` 可直接传入字符串列表快速入库）。
- `delete`：从向量存储中删除指定文档。
- `similarity_search`：基于向量相似度执行检索，返回匹配结果。

#### 3. RAG 完整流程

分为**索引阶段（存储）****和****查询阶段（检索）**：

- **索引阶段**：

1. 1. 原始文档 → 嵌入模型 → 生成嵌入向量
   2. 将向量与原文存入向量数据库

- **查询阶段**：

1. 1. 用户查询文本 → 嵌入模型 → 生成查询向量
   2. 向量库执行 `similarity_search` → 返回 Top-k 最相似文档

- **生成阶段**：将用户问题与检索到的参考资料一同封装到提示词模板，输入大模型生成回答。

#### 核心要点

- 向量存储是 RAG 技术的核心组件，负责高效存储和检索文本语义信息。
- `add_texts` 是快速向量化文本的便捷方法，适合批量导入资料。
- 完整 RAG 流程 = 向量存储 + 检索匹配 + 提示词封装 + 大模型生成，实现 “基于外部知识回答问题”。
