## 一、先明确：Agent 架构 = 「思考 - 行动」的组织方式

Agent 架构的本质，是**如何调度****大模型****的推理能力与工具执行能力**，完成从「目标」到「结果」的闭环。不同架构，核心区别就两点：

- 「思考」和「行动」的顺序（先想再做？边想边做？）
- 「思考」的形态（线性？树状？多角色协作？）

## 二、经典单 Agent 架构

1. ### ReAct 架构（Reason + Act）

**核心思想**：边思考，边行动，循环迭代。

- 流程：
  - **Reason**：大模型先输出「我要做什么、为什么这么做」
  - **Act**：调用工具执行动作
  - **Observe**：接收工具返回结果
  - 回到步骤 1，直到目标完成
- 特点：
  - ✅ 简单直观、工程落地成本最低
  - ✅ 适合大多数工具调用场景（查资料、写代码、自动化操作）
  - ❌ 复杂任务容易「走偏」，缺乏全局规划
- 代表：LangChain 基础 Agent、AutoGPT 早期版本

plaintext

```
目标 → 思考(Reason) → 行动(Act) → 观察(Observe) → 思考 → ... → 完成
```

### Plan-Act 架构（先规划，后执行）

**核心思想**：先一次性生成完整计划，再按顺序执行，不轻易修改。

- 流程：
  - **Plan**：大模型把目标拆解成「步骤清单」（比如 1. 查资料 2. 搭框架 3. 写内容）
  - **Act**：按步骤依次调用工具，逐个完成
  - 全部步骤执行完毕即结束
- 特点：
  - ✅ 执行高效、路径清晰，适合确定性强的任务
  - ❌ 灵活性差，计划一旦不合理很难修正
- 适合场景：固定流程任务（如订机票、报表生成）

plaintext

```
目标 → 生成完整计划 → 按步骤执行 → 完成
```

### Plan-Act-Reflect 架构（带反思的进阶版）

**核心思想**：在 Plan-Act 基础上，加入「自我修正」能力。

- 流程：
  - **Plan**：生成初始计划
  - **Act**：执行一步或多步
  - **Reflect**：复盘当前结果，判断计划是否合理
  - 若不合理 → 重写计划 → 继续执行
- 特点：
  - ✅ 抗错能力强，复杂任务准确率更高
  - ✅ 能从错误中学习，逐步逼近目标
  - ❌ 耗时更长、token 消耗更高
- 代表：Reflexion、Self-Reflect
- 适合场景：长流程复杂任务（如写论文、开发功能、调试代码）

plaintext

```
目标 → 计划 → 执行 → 反思 → （修正计划/继续执行）→ ... → 完成
```

### Tree-of-Thought (ToT) 树式思考架构

**核心思想**：不一条路走到黑，用「树状搜索」探索多条可能路径。

- 流程：
  - **Generate**：对当前状态生成多个候选下一步
  - **Evaluate**：评估每个候选的价值 / 可行性
  - **Search**：选择最优分支继续探索，直到找到解
- 特点：
  - ✅ 逻辑推理能力极强，适合解难题
  - ❌ 计算成本极高，工程落地难度大
- 适合场景：数学推理、逻辑题、复杂代码调试

plaintext

```
目标 → 生成多路径 → 评估选择 → 深入探索 → ... → 找到最优解
```

## 三、进阶：多 Agent 协作架构（企业级方向）

1. ### Multi-Agent 架构（多智能体分工）

**核心思想**：把复杂任务拆给多个「专业 Agent」，分工协作完成。

- 典型角色分工：
  - **Manager Agent**：统筹任务、分配工作、协调进度
  - **Worker Agent**：执行具体子任务（如写代码、查资料、做测试）
  - **Reviewer Agent**：校验结果、提出修改意见
- 流程：
  - Manager 接收目标 → 拆解任务 → 分配给 Worker
  - Worker 各自执行 → 提交结果
  - Reviewer 校验 → 反馈修改 → 最终汇总
- 特点：
  - ✅ 能处理超复杂、跨领域任务
  - ✅ 扩展性强，可按需新增角色
  - ❌ 角色间协调成本高，容易出现沟通混乱
- 代表：AutoGen、MetaGPT、ChatDev
- 适合场景：软件开发、内容创作、企业级自动化

plaintext

```
目标 → Manager 拆解 → 多 Worker 并行执行 → Reviewer 校验 → 汇总输出
```

### Hierarchical Multi-Agent 分层架构

**核心思想**：在多 Agent 基础上，加入「层级」，上层做规划决策，下层做执行。

- 典型分层：
  - **高层 Agent**：制定全局策略、拆解大任务
  - **中层 Agent**：管理子任务、协调下层执行
  - **底层 Agent**：直接调用工具、完成具体操作
- 特点：
  - ✅ 结构清晰，适合超大规模复杂系统
  - ❌ 层级越多，响应延迟越高
- 适合场景：工业级 AI 系统、复杂业务流程自动化

## 四、特殊方向：知识增强与端到端架构

1. ### Agent + RAG 架构（知识型 Agent）

**核心思想**：在任意基础架构上，叠加「检索增强」模块，解决大模型知识过时、幻觉问题。

- 流程：
  - 目标输入 → 检索相关知识库 / 文档
  - 把检索结果注入 Prompt → 再进入原有架构（ReAct/Plan-Act 等）
  - 基于外部知识完成推理与执行
- 特点：
  - ✅ 低幻觉、知识更准确
  - ✅ 适合专业领域（法律、医疗、企业客服）
- 本质：**在原有 Agent 架构上，增加一个「知识输入层」**

### 端到端可训练 Agent 架构（研究向）

**核心思想**：不依赖手工 Prompt，直接用强化学习 / 监督学习训练整个「思考 - 行动」策略。

- 流程：
  - 把「目标 - 状态 - 行动 - 奖励」封装成马尔可夫决策过程
  - 用 RLHF/RLAIF 等方法训练策略网络
  - 模型直接输出最优行动序列
- 特点：
  - ✅ 理论上更智能、更通用
  - ❌ 训练成本极高、工程落地难度大
- 代表：WebGPT、MineDojo
- 适合场景：前沿研究、特定环境交互（如游戏、机器人）
