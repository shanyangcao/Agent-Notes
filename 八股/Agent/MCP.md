### Skill 和 CLI 了解吗，MCP 和 Skill、CLI 对比有哪些优劣势？token 哪个用的多？

**概念**

- **Skill**：早期 Agent 工具实现，硬编码在 Agent 内部，工具逻辑、参数、描述写死在代码里
- **CLI**：命令行调用，通过执行终端命令调用工具，依赖系统环境
- **MCP**：标准化协议，解耦 Agent 与工具，实现跨模型、跨工具的标准化调用

**优劣势**

1. **MCP 优势**

- - 标准化：统一调用格式，无需适配不同工具 / 模型
  - 解耦：工具独立部署，Agent 不用改代码即可接入新工具
  - 能力全：支持工具调用、资源读取、提示词复用，不止是执行指令
  - 跨环境：本地 / 远程、不同模型都能兼容

1. **MCP 劣势**

- - 协议开销大，**token 消耗最多**
  - 部署复杂，需要维护 Server/Client/Host 组件

1. **Skill 优势**：简单轻量、token 最少，适合单一固定工具场景；劣势：硬编码、扩展性极差
2. **CLI 优势**：无需开发，直接调用系统命令；劣势：依赖环境、无安全隔离、跨平台差、token 中等

**token 消耗排序**：MCP > CLI > Skill

### 你说 tokenMCP 消耗更多是吧，那 Skill 和 CLI 分别什么时候用呢？

- **Skill 适用场景**：工具固定、逻辑简单、长期不迭代，比如固定的计算器、时间查询、简单数据格式化，追求低 token、低开发成本
- **CLI 适用场景**：快速原型验证、临时调用系统工具（文件操作、脚本执行），不想写复杂封装，环境可控、安全风险低的场景
- **MCP 适用场景**：多工具动态接入、跨模型 / 跨系统协作、企业级 Agent 编排，需要安全隔离、标准化治理的正式项目

### MCP 的三大核心组件 Host、Client、Server 有写过吗，都什么作用？

1. **Host（宿主）**：Agent / 大模型所在的主体，负责发起调用、解析工具返回结果、决策下一步动作，是 MCP 的调用发起方
2. **Client（客户端）**：集成在 Host 里，负责和 Server 建立连接、序列化请求、反序列化响应，完成协议通信，屏蔽底层细节
3. **Server（服务端）**：工具 / 能力的提供方，封装具体工具逻辑（数据库、文件、API），暴露标准化接口，处理 Client 的调用请求，返回执行结果

一句话总结：**Host 做决策，Client 做通信，Server 做执行**

### MCP 和 Function Calling 的核心差异了解吗

1. **定位不同**

- - Function Calling：大模型原生能力，是**单次的函数调用指令**，绑定模型本身
  - MCP：是**通用通信协议**，独立于模型，是一套完整的工具交互标准

1. **能力范围**

- - Function Calling：仅支持工具调用（执行动作）
  - MCP：支持工具调用、资源读取、提示词共享、双向交互、会话上下文保持

1. **扩展性**

- - Function Calling：工具元数据写死在 prompt，新增工具要改 prompt、消耗大量 token
  - MCP：Server 主动暴露工具列表，Host 动态拉取，无需硬编码，扩展性极强

1. **跨模型**

- - Function Calling：不同模型格式不兼容，OpenAI/Anthropic 格式完全不同
  - MCP：统一协议，任意模型都能接入

1. **部署形态**

- - Function Calling：模型侧直接调用，无独立服务
  - MCP：Server 可独立部署，支持远程调用、沙箱隔离

### M×N 集成问题有了解过吗，MCP 怎么解决的

### M×N 集成问题

M 个大模型、N 个工具，传统方式需要 M×N 次适配，每个模型要单独适配每个工具，开发成本爆炸，扩展性极差。

### MCP 解决方案

MCP 作为**中间标准化协议层**：

1. 工具只需要适配 1 次 MCP 协议（实现 MCP Server）
2. 模型只需要适配 1 次 MCP Client
3. 最终复杂度从 **M×N 降为 M+N**，实现一次开发、全模型全工具互通，彻底解决集成爆炸

### MCP 和 HTTP API 的区别是什么？

1. **通信目标**

- - HTTP API：通用数据传输，面向业务数据增删改查
  - MCP：专门面向**AI Agent 工具调用**，适配大模型的思考、调用、重试、会话上下文

1. **交互模式**

- - HTTP API：单向请求 - 响应，无会话上下文，无状态
  - MCP：双向流式交互，支持长会话、上下文保持、工具调用重试、多轮编排

1. **元数据能力**

- - HTTP API：需要手动写接口文档，模型无法自动发现
  - MCP：Server 自动暴露工具元数据（名称、参数、描述），Host 主动发现，开箱即用

1. **安全机制**

- - HTTP API：通用 token、签名
  - MCP：内置沙箱隔离、权限管控、密钥管理、调用审计

1. **适用场景**

- - HTTP API：业务系统对接、通用数据接口
  - MCP：Agent 工具编排、大模型能力扩展

### 一次完整的 MCP 工具调用详细流程是什么？

1. **工具发现**：Host 启动后，Client 主动拉取 MCP Server 暴露的所有工具列表、参数、描述
2. **用户提问**：用户输入指令，Host 将指令 + 工具元数据输入大模型
3. **决策调用**：大模型判断需要调用哪个工具，生成符合 MCP 协议的调用请求
4. **协议封装**：Client 将请求序列化为 MCP 标准格式，发送给 Server
5. **工具执行**：Server 解析请求，调用本地封装的工具逻辑（数据库 / 文件 / 脚本）
6. **结果返回**：Server 将执行结果按 MCP 协议返回给 Client
7. **结果解析**：Client 反序列化结果，交给 Host
8. **生成回答**：大模型结合工具结果，整理成自然语言回答用户
9. **多轮循环**：如需多次调用，重复步骤 3-8

### MCP 中的工具发现机制是主动拉取还是被动推送？

**主动拉取**

1. Host 侧的 Client 主动向 MCP Server 发起请求，拉取 Server 的 Tools、Resources、Prompts 元数据
2. Server 被动响应，不会主动推送信息
3. 优势：Host 可以按需拉取、缓存工具列表，降低 token 消耗，提升稳定性

### Agent 系统中基于 MCP 做多工具编排有做过吗？怎么做

1. **工具接入层**：将所有工具（数据库、文件、API、脚本）封装为独立 MCP Server，标准化暴露接口
2. **编排决策层**：Agent（Host）维护工具依赖关系、调用顺序、失败重试策略，通过大模型做动态决策
3. **协议通信层**：Client 统一和所有 Server 通信，屏蔽不同工具的底层差异
4. **执行调度层**：支持串行、并行、条件分支编排，比如先查数据库，再调用计算工具，最后生成报告
5. **监控容错层**：做调用超时、失败重试、熔断降级，保证编排稳定性

实战做法：用 MCP 解耦工具，大模型负责业务逻辑编排，代码层做调度容错，实现低代码的多工具协作。

### MCP 的安全机制知道哪些？沙箱隔离、密钥管理怎么做？

### 核心安全机制

1. **沙箱隔离**：MCP Server 独立进程 / 容器部署，限制文件读写、网络访问、系统命令执行，防止越权操作；不同 Server 互相隔离，一个工具出问题不影响全局
2. **密钥管理**：Client 和 Server 通过密钥 / Token 双向认证，通信全程加密；密钥集中管理，支持轮换、权限分级，不同 Agent 分配不同密钥
3. **权限管控**：工具粒度的权限配置，限制 Agent 能调用哪些工具、能操作哪些资源
4. **调用审计**：记录每一次工具调用的入参、出参、调用方、时间，可追溯可排查
5. **输入校验**：Server 侧严格校验调用参数，防止注入攻击

### 项目里看你有用 MCP，什么是 MCP？

MCP 全称**模型上下文协议（Model Context Protocol）**，是一套**AI Agent 和外部工具、资源交互的标准化开源协议**。简单说，它是 Agent 的「通用接口标准」，解耦大模型和工具，让任意大模型都能零修改接入任意 MCP 工具，解决多模型多工具的集成爆炸问题，是 Agent 工程化落地的核心协议。

### 我们常说 MCP 是 AI 的 USB‑C 接口，你怎么理解这句话

USB‑C 的核心是**通用、标准化、即插即用、跨设备兼容**，MCP 完全对应：

1. **通用**：USB‑C 适配手机、电脑、平板；MCP 适配任意大模型、任意工具
2. **标准化**：统一接口规范，不用为每个设备单独适配；MCP 统一协议，不用为每个模型单独开发工具
3. **即插即用**：插上就能用；MCP Server 部署后，Agent 自动发现工具，无需改代码
4. **能力扩展**：USB‑C 支持充电、数据、视频；MCP 支持工具调用、资源读取、提示词共享

一句话：MCP 就是 AI 世界的通用接口，解决 Agent 工具接入的碎片化问题。

### MCP Server 的 Tools、Resources、Prompts 了解吗，都啥时候用啊

1. **Tools（工具调用）**：用于**执行动作、外部操作**，比如查数据库、调用 API、运行脚本、文件修改，是最常用的能力
2. **Resources（资源读取）**：用于**只读获取信息**，比如读取本地文件、知识库、配置、静态数据，不做修改
3. **Prompts（提示词复用）**：用于**共享预设提示词**，比如通用指令、模板、角色设定，Agent 直接复用，减少重复开发

### MCP 基于啥知道吗

底层基于 **JSON‑RPC 2.0** 规范，采用**流式 JSON**传输；通信层支持 **Stdio（本地进程通信）、HTTP、WebSocket** 三种方式；是开源的、跨语言的、跨平台的协议。

### MCP 和 RAG 区别是什么

1. **核心定位**

- - RAG：**读取静态知识**，解决大模型幻觉、知识更新问题，侧重信息检索
  - MCP：**执行外部动作 + 读取资源**，解决 Agent 工具调用、外部能力扩展，侧重工具编排

1. **能力范围**

- - RAG：只能查数据、读文档，不能做修改、执行、计算
  - MCP：既能读资源（对应 RAG 能力），也能写数据、调用 API、执行脚本、编排工具

1. **技术架构**

- - RAG：依赖向量库、检索引擎、文档解析
  - MCP：依赖标准化协议、Server/Client 通信

1. **适用场景**

- - RAG：知识库问答、企业文档检索、静态信息查询
  - MCP：Agent 自动化、多工具协作、系统操作、业务流程执行

1. **互补关系**：RAG 可以封装为 MCP 的一个 Server，MCP 调用 RAG 做知识检索，两者是互补而非替代
