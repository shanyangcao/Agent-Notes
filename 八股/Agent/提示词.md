###  提示词模板是怎么构建的？  

- **明确目标**：先确定提示词要解决什么问题（比如写单测、调用工具、做任务规划）。
- **角色定义**：给模型设定身份（比如 “你是资深 Java 单元测试工程师，熟悉 JUnit5”）。
- **规则约束**：明确输出格式、限制条件（比如 “输出必须是可直接运行的 JUnit5 代码，不能包含解释性文字，所有依赖用 import 导入”）。
- **示例引导**（Few-shot/CoT）：给 1-2 个正确示例，让模型模仿，比如给一段业务代码和对应的正确单测，让模型学习格式和逻辑。
- **输入占位符**：用变量把动态内容（比如用户输入的代码、需求）和模板结合起来，比如`{{business_code}}`、`{{test_requirements}}`。
- **效果迭代**：通过人工 / 自动化评估（比如看生成的单测覆盖率、通过率），不断调整模板的约束、示例和措辞，优化模型输出。

###  为什么写好 Prompt 很重要  

 因为 Prompt 是我们利用模型 In-Context Learning 能力的核心方式。模型本身的参数是固定的，没法为每个业务场景都微调一遍。我们只能通过精心设计的提示词、示例和上下文，让模型在运行时临时理解任务规则，完成不同的业务需求。
